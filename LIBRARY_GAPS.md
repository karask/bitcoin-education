# Remaining library and model boundaries

The browser runtime uses published `bitcoin-utils 0.8.7`. Block construction now
uses `get_block_subsidy`, `create_coinbase_transaction`, and
`trace_merkle_root` from `bitcoinutils.learning`; mining uses `BlockHeader`.
These return real coinbase and transaction bytes, TXIDs, Merkle pairs, and an
80-byte header. The website does not implement Bitcoin cryptography.

The constructed block is an educational candidate. The user-supplied starting
UTXO is not checked against the chain. Two independent example transactions
have library-generated bytes, while their previous outputs, signatures, and
fees are assumptions. The selection budget covers ordinary legacy transaction
virtual bytes, excludes coinbase and header, and is not a consensus block-weight
limit or Bitcoin Core package-selection policy. Coinbase payout uses a fixed
example P2PKH script. No SegWit witness commitment is constructed.

Mining uses the actual candidate Merkle root but an illustrative zero previous
block hash, timestamp, and easy target. A successful nonce in that exercise is
not a block valid on mainnet or testnet. Block propagation separately assumes a
valid block with the selected transactions was found and models compact relay,
independent node acceptance, and confirmations. It does not transmit a block or
validate a chain.

Further library work for full block building or validation would include whole
block serialization, witness commitments for SegWit transactions, contextual
proof-of-work and chain rules, and UTXO-backed transaction and script validation.
Those features should live in `python-bitcoin-utils`; the website would then
show their actual outputs.
